## What an ordinary USB/I2C adapter can and cannot replace

For BQ40Z50, documented SMBus commands allow data-flash configuration, calibration and production-image replay. That does not create the cell's chemistry data. TI support explicitly calls for EV2400 and bqStudio for normal ChemID programming; an alternative involves GPCCHEM characterization and a TI-supplied image. No supported native Mac/Linux chemistry-creation path was verified. A generic adapter or Raspberry Pi is therefore not budgeted as a complete replacement. Never invent a Samsung50E ChemID or assume a nominal-capacity match is sufficient. [TI chemistry answer](https://e2e.ti.com/support/power-management-group/power-management/f/power-management-forum/1316617/bq40z50-how-to-program-chemistry-id-without-bq-sutdio-by-smbus-commands), [R2 technical reference](https://www.ti.com/lit/ug/sluubk0b/sluubk0b.pdf).

The [supported MKS adapter](https://www.ti.com/tool/MKST-3P-ALT-EV2300) is a real alternative. Its [manufacturer ordering page](https://www.mkstechnology.com/mks-sai) exposes a PayPal Buy Now button but no readable price. No checkout or contact was initiated. Its price remains unknown; it is not assumed cheaper. bqStudio on Wine or Windows ARM/USB passthrough is not a verified commissioning solution. [TI platform answer](https://e2e.ti.com/support/power-management-group/power-management/f/power-management-forum/879823/bq40z50-r2-evaluating-setting-up-bqstudio-without-windows-host).

MAX17320G22+ is a 4×4mm TQFN24, high-side protector, balancer and coulomb-counting/model gauge. The EZ model removes mandatory custom cell characterization for ordinary applications, but does not promise a particular Samsung50E accuracy. Its datasheet limits EZ empty-voltage models to3.0–3.4V and identifies chemistries needing custom characterization for best performance. The official evaluation GUI still requires Windows. A host-configured path needs reviewed values for cell count, capacity, sense resistance, termination, empty voltage, thermistors and every protection threshold. [ADI product](https://www.analog.com/en/products/max17320.html), [Rev12 datasheet](https://www.analog.com/media/en/technical-documentation/data-sheets/MAX17320.pdf).

ADI publishes the NVM update sequence and says EZ does not need a custom characterization file. Configuration starts in shadow RAM; read back and test it before committing. There are only seven configuration slots. Preserve remaining-slot count and never burn on every boot or retry blindly. No secret provisioning or irreversible locking is needed for these blinds. A custom host fixture can follow this documented interface, but its correctness has not yet been demonstrated. [Battery-pack guide](https://www.analog.com/media/en/technical-documentation/user-guides/max17320-battery-pack-implementation-guide.pdf), [host-software guide](https://www.analog.com/media/en/technical-documentation/user-guides/max17320-software-implementation-guide.pdf).

## Bench qualification required whichever gauge is selected

1. Start with a current-limited, independently adjustable three-cell battery simulator. Keep the motor unplugged and charger disabled. Verify all raw/group/pack voltages and NTC channels before enabling the protection FETs. No fault injection uses real lithium cells.
2. Read device identity/firmware, preserve factory settings, compare every programmed value with a versioned manifest, and verify power-cycle retention. Use a separate commissioning mode with runtime firmware held inactive on the bus.
3. Calibrate or verify voltage, zero-current offset, known positive/negative current and thermistor values against independent instruments. Check charge/discharge sign, shunt bypass paths and all cell-group values.
4. On the simulator, cross each configured over/undervoltage threshold separately and measure trip/recovery timing. Verify overtemperature/undertemperature and open/short NTC behavior, current overload response, charger-present recovery and MCU-reset behavior. Do not exceed any component rating while testing short-circuit protection; use a bounded electronic-load stimulus.
5. Verify balancing direction/current with deliberately unequal simulated group voltages. Verify communication failure leaves autonomous protection active. Disable automatic motion after any pack-protection event until requalification.
6. With the simulator able to sink current, test disconnect during deceleration and a full-pack charging-inhibit event. Measure the real dump-clamp voltage, resistor/MOSFET temperature and pulse energy. A passing ideal-clamp SPICE calculation does not close this test.
7. Only after circuit review and the simulator tests, perform controlled normal charge/discharge validation with the assembled, fused pack and log reference coulombs versus reported SOC. Test the actual low-load/long-idle profile and loaded cutoff. Archive results per unit; do not advertise an accuracy number before measuring it.

Initial configuration proposals must remain non-programmable until exact cells, shunt/FET ratings, NTC curve and measured motor envelope are resolved. A reset-default gauge configuration is not acceptable for installation. The independent pack fuse and protected raw-sense harness are circuit requirements, not firmware settings.

**Current direction:** MAX17320G22+ on the protected battery carrier, keeping all raw cell taps on that assembly. A direct host through the controller's USB/I2C commissioning mode avoids a mandatory EV2400 purchase; common bench instrumentation and fixture costs still apply. Keep BQ40Z50-R2 as the supported-tooling fallback. Final configuration is not frozen and no equipment has been purchased.

## Direct-host implementation boundaries

Rev12 Tables97/98 publish the ROM EZ selection and default model parameters. This makes a direct I2C Mac/Linux tool a documented implementation path, although our implementation and Samsung50E accuracy remain unvalidated. Use 7-bit I2C address0x36 for normal registers and0x0B for shadow addresses0x180–0x1FF, with little-endian16-bit values. The proposed10mΩ shunt implies0.5mAh capacity units and nominal10Ah capacity0x4E20; nRSense metadata would be0x03E8 (10µΩ units). These are isolated derivations, **not a complete programming image**. The3S NCELLS field is1. All protection, NTC, charge prescription and model fields need a reviewed manifest.

Rev12 tBLOCK is368ms typical but7360ms maximum: a programmer must poll NVBusy with a bounded timeout beyond the maximum, not use the old guide's fixed368ms delay. The firmware tooling currently supports readback/offline comparison only. Gauge current updates are much slower than the motor control loop; DRV current limiting and feedback remain the fast overload path. [Rev12 datasheet](https://www.analog.com/media/en/technical-documentation/data-sheets/MAX17320.pdf).
