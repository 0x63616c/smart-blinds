# pd12v6 — USB-C PD → 12.6 V / 4.5 A supply

Status: layout complete, DRC clean (0 violations, 0 unconnected), awaiting review.
Source: `hw/boards/pd12v6.ato`. Layout: `hw/layouts/pd12v6/pd12v6.kicad_pcb`.
Regenerate everything: `hw/scripts/review.sh` (add `--open` to launch KiCad).

## What it is

A USB-C Power Delivery sink that outputs a fixed 12.6 V on an XT30PW-M, with a
hard current limit, plus a 3-pin header that passes the USB-C D−/D+ pair through.
It is **not** a charger: the 3S2P pack side (balancing, CC/CV termination, protection)
lives downstream. This board only has to make a clean, current-limited 12.6 V rail.

## Requirements → decisions

| Requirement | Decision | Why |
|---|---|---|
| Works on 65 W and 100 W chargers | Request **20 V** PD profile (CH224A, CFG1 = 120 kΩ) | Both charger classes offer 20 V. Available current is 3.25 A (65 W) or 5 A (100 W); the buck's input current is ~3 A at full load so a 65 W brick is enough. |
| 12.6 V at 2–5 A | TPS54560 (60 V / 5 A buck), 12.56 V set by 147 k / 10 k on FB | Headroom for 20 V in; 5 A switch rating; 0.8 V reference. 12.56 V keeps a 3S pack a hair under 4.2 V/cell. |
| Limit output current | 4.5 A constant-current clamp (20 mΩ shunt in the return + LM358 integrator → FB via 100 k + 1N4148W) | Keeps the board inside a 65 W budget and gives a real CC knee instead of relying on the buck's hiccup limit. |
| Don't brown-out the charger | UVLO: EN divider 820 k / 56 k → start ≈ 19 V | Buck only runs once 20 V PD negotiation has succeeded. |
| Data pass-through | 1×3 header D−, D+, GND (pin 1 = D−) | Header GND is OUT_RTN, i.e. the low side of the shunt: ≤ 90 mV offset at 4.5 A, fine for USB data. |
| Smallest 2-layer board | 41 × 36 mm, 2 mm corner radius, 4 × M2 grounded holes | Set by the XT30PW, inductor and USB-C footprint, not by routing. |
| USB-C overhangs the edge | USB-C at x = 4.2 mm, shell past Edge.Cuts | Cable plugs in without hitting an enclosure wall. |
| Indicate on | LED2 "PD" on VBUS (20 V present), LED1 "ON" on VOUT | Two LEDs so you can tell "no PD contract" from "buck fault". |
| JLCPCB in-stock | all parts picked by LCSC ID (see BOM) | `hw/build/builds/pd12v6/pd12v6.bom.csv` |

## Circuit blocks

- **USB-C + PD sink (U3 CH224A):** CC1/CC2 to the receptacle, CFG1 = 120 kΩ to GND
  selects 20 V (table 5-1). 1 µF on VBUS at the chip. PG_n is routed but unused.
  SMBJ24A TVS across VBUS at the connector.
- **Buck (U1 TPS54560):** 2 × 10 µF 1210 + 100 nF input, 100 nF boot, 240 kΩ RT (~400 kHz),
  SS56 catch diode, 10 µH 10 A inductor, 2 × 47 µF 1210 output, comp 20 kΩ + 8.2 nF with
  47 pF HF roll-off.
- **Current clamp (U2 LM358):** shunt R13 = 20 mΩ 2512 between OUT_RTN and GND.
  The op-amp integrates (I_SENSE − I_REF); when the shunt drop exceeds the reference
  (divider from VBUS) the integrator pulls FB up through D2/R5, folding the output
  voltage back. Limit ≈ 4.5 A; trim with R9/R10/R12.
- **Indicators:** LED2 (0603 red) on VBUS via 820 k…; LED1 (0603 green) on VOUT via 4.7 k.

## Layout notes

- Input caps hug U1's VIN/GND; SW node is the short loop U1 → D1 → L1.
- Output return comes back through R13 on the bottom-right; Kelvin sense taps at the
  shunt pads go to U2 on short top-layer traces.
- Bottom layer is a solid GND pour; only the sense/inject/CC signals cross it.
- All footprint silkscreen is stripped and references hidden on purpose so the board
  reads as labels only. The library-mismatch DRC rule is set to ignore in the
  `.kicad_pro` because of this.

## Toolchain quirks (so the scripts stay repeatable)

- atopile 0.15.9 only parses the KiCad 9 file grammar. KiCad 10's pcbnew writes a v10
  file, so `layout_pd12v6.py` downgrades it after saving: version/generator header,
  `tenting`/`covering`/`plugging`/`capping`/`filling` tokens, and the net table that
  KiCad 10 dropped (`(net N "NAME")` on pads, `(net N)` on tracks, `(net N)` +
  `(net_name …)` on zones).
- KiCad 10 SWIG: any `Remove()` invalidates other wrappers. The script does all removals
  first, saves, reloads, then continues.
- `kicad-cli pcb drc` must be run with `--refill-zones` or it reports hundreds of
  bogus zone clearance errors.
- No atopile login is used; parts are fetched with `hw/scripts/fetch_part.py Cxxxx`.
