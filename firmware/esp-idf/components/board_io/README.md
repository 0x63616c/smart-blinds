# C6 board I/O, disabled diagnostic component

The bring-up target compiles this component but does not instantiate it. Default application behavior is unchanged: no board GPIO is configured and the motor remains unavailable. The component has no motor/charge/encoder-enable method, waveform start or WDI pulse operation.

Explicit `initialize()` is reserved for the reviewed board/fixture. It preloads and enables HIGH on MOTOR_REQUEST_N, CHARGE_ALLOW_N, ENCODER_ALLOW_N and WDI, then LOW on IN1/IN2. Request comes first so watchdog and motor remain inhibited while peripheral pin routing changes. Inputs use the circuit's external pulls. Pad readback checks the requested levels; it does not prove the external gate, regulator or motor terminals are safe.

It allocates a stopped PCNT quadrature unit on GPIO6/7, both channels, overflow watch points and a provisional 1 µs glitch filter. It does not enable/start counting or power the encoder and reports no valid position. The quadrature action follows [Espressif's pinned example](https://github.com/espressif/esp-idf/blob/v5.5.4/examples/peripherals/pcnt/rotary_encoder/main/rotary_encoder_example_main.c); the sign, edge rate, noise tolerance and counts/revolution remain commissioning data. GPIO pulls installed by PCNT are explicitly removed. A future active port must add bounded count handling, a session epoch, awake power-management locks and stop/disable before sleep. Deep sleep invalidates count continuity.

MCPWM gets a stopped timer and two non-inverted, loopback-enabled generators held LOW. The 1 MHz/50-tick (20 kHz) period is a provisional configuration only. There are no comparator waveforms or timer enable/start calls. Failure attempts every independent OFF operation, then releases allocated resources in dependency order. No automatic reinitialization follows a failure. Call `shutdown()` and inspect its result before destroying a used component; errors cannot prove resources or physical pins recovered. An unused object's destructor has no pin side effects.

`DisabledInputs` exposes raw button, shared motor-fault and optional-reference levels only while the OFF readback succeeds. GPIO21 LOW may come from the DRV8874 or the latched regeneration thermal gate; the pin cannot distinguish these causes. An unexpected ON readback permanently faults this instance and requests OFF; successful recovery does not restore input validity. Tear down and construct a fresh instance for an explicit reviewed retry. An optional-reference level has no calibrated meaning by itself. Motor current and pack readiness are not fabricated. Native USB12/13 and straps4/5/8/9/15 remain untouched. WDI16 never becomes UART logging or a background pulse source.

The portable `blinds::io::Buttons` policy expects a <=10 ms control-task sample cadence. Any raw press during active/prepared movement, both buttons or an ambiguous direct button swap emits STOP without debounce. A 20 ms stable full release is required before another gesture; a held boot/STOP button cannot start movement. An idle short tap emits its endpoint action after debounced release. A single 1.5 s hold emits one service request and suppresses the normal tap; it does not enter calibration, jog or energize anything by itself. A >50 ms sample gap or reversed clock emits STOP and requires release again. Pass `active=true` for prepared, armed or moving sessions. Reference and fault checks still belong to the controller.

Host fault-injection tests exercise each portable initialization/stop operation and button gestures. They do not execute ESP-IDF's GPIO/peripheral implementation or validate waveforms. The new C6 component is awaiting the next pinned CI cross-build; no hardware has been attached. Primary APIs: [GPIO](https://docs.espressif.com/projects/esp-idf/en/v5.5.4/esp32c6/api-reference/peripherals/gpio.html), [PCNT](https://docs.espressif.com/projects/esp-idf/en/v5.5.4/esp32c6/api-reference/peripherals/pcnt.html), [MCPWM](https://docs.espressif.com/projects/esp-idf/en/v5.5.4/esp32c6/api-reference/peripherals/mcpwm.html).
